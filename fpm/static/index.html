Federated Sensor Workflow

This dashboard runs a federated next-event prediction workflow on the Chinook smart-home dataset. Each participant is a Docker client with private trial data. You send an LTL filter and model choice to all clients; only participants whose behavior matches the filter train locally and return results.

Query

Configure what to broadcast to every client. The LTL filter selects participants by behavioral pattern (empty means all clients). The model is trained independently on each matched client. Enable behavioral grouping to additionally cluster matched clients and run pooled evaluation on the server. The evaluation protocol controls how train/test splits are built for both per-client and grouped metrics.

Federated Client Results

These results come directly from each Docker client after local training. Matched means the participant passed the LTL filter on their training trials. Client accuracy is that participant's next-event accuracy using the model you selected above (tree, Markov, etc.), evaluated with the chosen protocol. Grouped Comparison

This section appears when behavioral grouping is enabled. Unlike the federated client table above, these metrics are computed centrally on the server by pooling test samples from all matched participants. Matched clients are clustered by behavioral profile, then several CASAS2-style decision-tree baselines are compared: one global model, one model per cluster, per-client local models, and Markov baselines. Accuracies here will usually differ from the client table because they use a different model (deep CASAS2 tree), different event encoding, and pooled evaluation across all participants rather than one local score per client.
